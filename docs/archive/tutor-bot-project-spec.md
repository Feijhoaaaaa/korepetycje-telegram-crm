# Telegram-бот для учёта занятий репетитора

## 1. Цель проекта

Создать максимально простой Telegram-сервис для преподавателя, который позволяет:

- привязать отдельный Telegram-чат к конкретному ученику;
- вести календарь занятий;
- добавлять, переносить, отменять и завершать занятия;
- фиксировать факт оплаты;
- видеть общий календарь по всем ученикам;
- выгружать историю занятий и оплат в Excel;
- автоматически публиковать изменения расписания в чат с учеником.

Основной принцип:

> Один Telegram-чат = один ученик + преподаватель + бот.

Ученик не использует интерфейс бота и не управляет расписанием. Бот нужен преподавателю как инструмент учёта, а ученику — только как источник уведомлений.

---

## 2. Основная модель работы

```text
Telegram-группа
├── Преподаватель
├── Ученик
└── Бот
      │
      ├── 📅 Календарь
      ├── ➕ Добавить занятие
      ├── 💰 Оплаты
      ├── 📚 История
      └── 📊 Excel
```

У преподавателя может быть несколько отдельных чатов:

```text
Анна + преподаватель + бот
Максим + преподаватель + бот
Александр + преподаватель + бот
Мария + преподаватель + бот
```

Бот связывает каждый Telegram `chat_id` с конкретным учеником.

Пример:

```text
chat_id 1001 → Анна
chat_id 1002 → Максим
chat_id 1003 → Александр
chat_id 1004 → Мария
```

---

## 3. Роли

### 3.1. Преподаватель

Может:

- подключать учебный чат;
- назначать ученика;
- создавать занятия;
- переносить занятия;
- отменять занятия;
- удалять ошибочно созданные занятия;
- отмечать занятие как проведённое;
- отмечать занятие как оплаченное или неоплаченное;
- просматривать будущие занятия;
- просматривать историю;
- видеть общий календарь;
- видеть неоплаченные занятия;
- выгружать Excel.

### 3.2. Ученик

Не имеет административного доступа.

Ученик:

- не регистрируется;
- не открывает панель;
- не создаёт занятия;
- не переносит занятия;
- не меняет статусы;
- не управляет оплатами.

Ученик только видит сообщения, которые бот публикует в общем чате.

---

## 4. Подключение нового чата

Преподаватель:

1. создаёт Telegram-группу с учеником;
2. добавляет бота;
3. отправляет команду:

```text
/setup@TutorBot
```

Бот:

1. получает `chat_id`;
2. определяет пользователя, вызвавшего `/setup`;
3. проверяет права пользователя;
4. сохраняет преподавателя;
5. создаёт запись учебного чата;
6. предлагает указать ученика.

### 4.1. Назначение ученика

Из-за ограничений Telegram Bot API бот не должен рассчитывать на получение полного списка участников группы.

Простой сценарий:

```text
Бот:
Ответьте командой /student
на любое сообщение ученика.
```

Преподаватель отвечает на сообщение ученика:

```text
/student
```

Бот получает `user_id` автора исходного сообщения и сохраняет его как ученика данного чата.

После настройки:

```text
✅ Чат подключён

Ученик: Александр
Преподаватель: Иван

[➕ Добавить занятие]
[📅 Ближайшие]
[📚 История]
```

## 5. Два режима интерфейса

### 5.1. Учебный чат

Используется для работы с конкретным учеником.

```text
Александр
Преподаватель
Бот
```

Бот уже знает, к какому ученику относится этот чат, поэтому преподавателю не нужно каждый раз выбирать ученика.

Основные действия:

```text
➕ Добавить занятие
📅 Ближайшие занятия
📚 История
💰 Оплаты
📊 Excel
```

### 5.2. Личный чат преподавателя с ботом

Используется для общей работы со всеми учениками.

Главное меню:

```text
📅 Сегодня
📆 Неделя
👨‍🎓 Ученики
💰 Неоплаченные
📊 Отчёт
```

Пример:

```text
📅 Сегодня — 24 сентября

15:00 — Анна
17:00 — Александр
18:30 — Максим
20:00 — Мария
```

## 6. Добавление занятия

Преподаватель нажимает:

```text
➕ Добавить занятие
```

Бот предлагает дату:

```text
Выберите дату:

[Сегодня]
[Завтра]
[23.09]
[24.09]
[📅 Другая дата]
```

После выбора даты:

```text
Выберите время:

[10:00] [11:00]
[12:00] [13:00]
[14:00] [15:00]
[16:00] [17:00]
[18:00] [19:00]

[⌨️ Ввести вручную]
```

Перед сохранением:

```text
Новое занятие

Ученик: Александр
Дата: 24 сентября 2026
Время: 17:00

[✅ Добавить]
[❌ Отмена]
```

После подтверждения запись сохраняется в БД.

В общий чат отправляется сообщение:

```text
📅 Новое занятие

24 сентября, 17:00
```

```text

[🔄 Перенести]
[❌ Отменить]
[🗑 Удалить]
```

## 8. Статусы занятия

Минимальный набор:

```text
planned
completed
cancelled
```

Описание:

| Статус | Значение |
|---|---|
| `planned` | занятие запланировано |
| `completed` | занятие проведено |
| `cancelled` | занятие отменено |

Для MVP отдельный статус `rescheduled` не нужен. При переносе изменяются дата и время, а в историю изменений можно добавить запись позже.

---

## 9. Перенос занятия

Преподаватель нажимает:

```text
🔄 Перенести
```

Выбирает новую дату и время.

После сохранения бот публикует в общем чате:

```text
🔄 Занятие перенесено

Было:
24 сентября, 17:00

Стало:
25 сентября, 18:00
```

В БД обновляется существующая запись занятия.

---

## 10. Отмена занятия

Преподаватель нажимает:

```text
❌ Отменить
```

Бот меняет статус:

```text
planned → cancelled
```

В общий чат:

```text
❌ Занятие отменено

25 сентября, 18:00
```

Удалять отменённые занятия из БД не нужно, поскольку они нужны для истории и статистики.

---

## 11. Завершение занятия

После проведения преподаватель нажимает:

```text
✅ Проведено
```

Статус:

```text
planned → completed
```

После этого бот спрашивает:

```text
Оплата:

[✅ Оплачено]
[⏳ Не оплачено]
```

---

## 12. Учёт оплаты

Для первой версии нужна только бинарная модель:

```text
paid
unpaid
```

Допустимо также значение:

```text
unknown
```

если преподаватель ещё не указал оплату.

Пример:

```text
24.09 17:00
✅ Проведено
💰 Оплачено
```

или:

```text
26.09 17:00
✅ Проведено
🔴 Не оплачено
```

На первом этапе не нужны:

- частичные оплаты;
- абонементы;
- разные валюты;
- способы оплаты;
- счета;
- чеки;
- скидки;
- автоматическая финансовая аналитика.

## 17. Возможная SQL-схема

Пример для PostgreSQL:

```sql
CREATE TABLE teachers (
    id BIGSERIAL PRIMARY KEY,
    telegram_user_id BIGINT NOT NULL UNIQUE,
    name TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE study_chats (
    id BIGSERIAL PRIMARY KEY,
    telegram_chat_id BIGINT NOT NULL UNIQUE,
    teacher_id BIGINT NOT NULL REFERENCES teachers(id),
    student_telegram_id BIGINT,
    student_name TEXT,
    active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE lessons (
    id BIGSERIAL PRIMARY KEY,
    study_chat_id BIGINT NOT NULL REFERENCES study_chats(id),
    lesson_datetime TIMESTAMPTZ NOT NULL,
    status TEXT NOT NULL DEFAULT 'planned',
    payment_status TEXT NOT NULL DEFAULT 'unknown',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

Ограничения статусов можно добавить через `CHECK`:

```sql
ALTER TABLE lessons
ADD CONSTRAINT lesson_status_check
CHECK (status IN ('planned', 'completed', 'cancelled'));

ALTER TABLE lessons
ADD CONSTRAINT payment_status_check
CHECK (payment_status IN ('unknown', 'paid', 'unpaid'));
```

## 20. Проверка прав доступа

Каждое административное действие должно проверять пользователя.

Пример логики:

```python
if callback.from_user.id != teacher.telegram_user_id:
    return
```

Нельзя полагаться только на то, что кнопка была показана преподавателю.

Проверка должна выполняться на сервере для каждого callback или административной команды.

## 32. Главный принцип UX

Преподаватель не должен:

- повторно выбирать ученика внутри его чата;
- заполнять длинные формы;
- вводить данные, которые бот уже знает;
- открывать внешний сайт для обычных действий;
- вручную вести Excel параллельно с ботом.

Цель интерфейса:

```text
1–3 нажатия → действие выполнено
```

Например:

```text
Добавить занятие
→ дата
→ время
→ готово
```

## 33. Итоговая схема

```text
                    ┌───────────────┐
                    │ Личный чат    │
                    │ преподавателя │
                    └───────┬───────┘
                            │
                            ▼
                     Telegram Bot
                            │
          ┌─────────────────┼─────────────────┐
          │                 │                 │
          ▼                 ▼                 ▼
      Чат Анны          Чат Максима      Чат Александра
          │                 │                 │
          └─────────────────┼─────────────────┘
                            │
                            ▼
                       PostgreSQL
                            │
                  ┌─────────┴─────────┐
                  ▼                   ▼
             Календарь             Excel
```

Основная идея сервиса: преподаватель ведёт расписание и учёт проведённых занятий прямо в Telegram, а бот автоматически связывает данные с нужным учеником и формирует журнал.
